# Triage: валидация ввода, проверка ответа AI, fallback на ручной разбор

## Запуск
```sh
node server.mjs          # http://127.0.0.1:3000 (порт — через PORT)
node --test server.test.mjs   # или npm test; Node.js 20+
```

## Где проверяется результат AI
`parseModelOutput()` в `server.mjs`: ответ модели должен быть валидным JSON-объектом, `topic` ∈ {`delivery`, `pricing`, `other`}, `draft` — непустая строка (после trim). Всё остальное считается неподходящим ответом.

## Что происходит при сбое
- Модель вызывается через `callModel()` с дедлайном 300 мс: в `classify` передаётся `AbortSignal`, и дополнительно стоит `Promise.race`, поэтому таймаут срабатывает, даже если провайдер игнорирует сигнал.
- Таймаут, исключение провайдера или невалидный ответ → HTTP 200 `{"status":"manual_review","topic":null,"draft":null}`.
- Некорректный ввод (битый JSON, не объект, нет `text`, не строка, пустая/из пробелов строка) → HTTP 400 `{"status":"invalid_input"}`. Модель в этом случае не вызывается.
- На странице: при `ready` показываются тема и редактируемый черновик с пометкой «проверьте перед отправкой»; при `manual_review` — сообщение менеджеру разобрать заявку вручную. Предыдущий результат очищается при каждой новой отправке.
- `mock-ai.mjs` не изменён.

## AI
Использовал Claude Code (Claude Opus 5.5) для написания кода и тестов.

## Что проверил сам
- Прогнал `node --test server.test.mjs`: 14 тестов, все зелёные.
- В браузере на http://127.0.0.1:3000:
  - «Когда будет доставка?» → тема «Доставка» и черновик; «Какая цена?» → «Цены и стоимость»; «Привет» → «Другое»;
  - пустой ввод и ввод из пробелов → «Введите текст заявки.»;
  - `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` → сообщение о ручном разборе;
  - после успешного ответа отправил `[error]`: старый черновик пропал, черновик клиенту по ошибке не уйдёт.
- Через curl: коды ответов (200 / 400), тела ответов по контракту; `[timeout]` возвращается примерно за 0,3 с, а не через 1,2 с, которые ждёт имитатор.
- Прочитал код, сгенерированный AI: где проверяется ввод (`parseInput`), где ответ модели (`parseModelOutput`), как работает таймаут (`callModel`).
- Принятое решение: строку из одних пробелов считаю пустой (400), черновик возвращаю с обрезанными пробелами по краям.

## Польза для менеджера
Менеджер получает тему и готовый черновик за доли секунды, а если AI ошибся, явно видит, что заявку нужно разобрать вручную. Измерять можно по медианному времени до первого ответа клиенту и по доле черновиков, отправленных без правок или с минимальными правками.
